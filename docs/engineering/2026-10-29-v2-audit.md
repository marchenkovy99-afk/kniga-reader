# kniga-reader v2.0 — architecture audit and release risks

**Status:** partial audit; implementation is not complete. Findings below refer to repository source on 2026-10-29. Real iPhone, live cloud accounts and commercial-performance targets remain unverified.

## Current architecture

- **App shell:** vanilla JavaScript in `reader/src/main.js` (single large coordinator), Vite build, compiled static PWA in `docs/`, GitHub Pages release job.
- **Document ingest:** `reader/src/importer.js`, `book-upgrade.js`, `document-model.js`. Existing UI accepts FB2, FB2 ZIP/FBZ, EPUB, TXT. PDF is **not implemented**, despite v2.0 requirement.
- **Pagination:** `dom-pagination.js` → `text-layout-engine.js` → `page-renderer.js` → `page-integrity.js`; legacy rollback in `legacy-pagination.js`. Source offsets remain UTF-16 for compatibility, with grapheme-safe boundaries in the DOM engine.
- **Presentation:** `reader/src/style.css` holds global/library/reader/components/themes and several mutually overriding layout generations. `theme()` in `main.js` updates the DOM root and theme-color meta tag.
- **Persistence:** IndexedDB `storage.js`, device-local pagination cache, `CloudSync` and `supabase-transport.js` for Supabase cloud state. No database migrations were made for this work.
- **PWA:** manifest with standalone mode, meta `black-translucent`, service worker and GitHub Pages build.
- **Verification:** Node tests, browser engine fixtures in Chromium/WebKit, installed-PWA emulation, GitHub Actions.

## Confirmed issues and risks

| Priority | Finding | Evidence / impact | Action |
| --- | --- | --- | --- |
| Critical | Latest main-branch build blocked by an obsolete browser test expecting removed page arrows | GitHub Actions run 40940371963 fails in `tests/reader-geometry.browser.mjs`, while `main.js` has no prev/next toolbar buttons | Update tests to the specified gesture-first interaction |
| Critical | Device-local pagination cache trusts in-memory entries and newly computed complete results without revalidating them | `pagination-cache.js` previously validated persisted disk entries, but not the memory hit or fresh output | Apply the same source/structure validation to every complete hit and result |
| High | Multiple conflicting CSS generations | `style.css` repeatedly assigns `--reader-top-inset`, `--reader-bottom-inset`, toolbar geometry and root/body palettes | Extract a canonical visual system and delete superseded declarations in a separately tested change |
| High | Cross-device deletion is not durable cloud state | `shelf-state.js` stores per-account hidden IDs locally; `supabase-transport.js` does not expose a cloud tombstone/delete protocol | Design versioned per-user tombstones, conflict behavior, RLS and migrations before changing data |
| High | Physical iOS status-bar appearance remains unverified | CSS paints page color under a translucent bar, but iOS owns system UI; WebKit desktop simulation cannot prove OS clock/contrast behavior | Validate all four themes on an installed physical iPhone after fresh launch and restart |
| High | PDF support absent | Current input/import and cloud accepted extensions exclude PDF | Add PDF-specific viewing and offline persistence without forcing DOM text pagination |
| Medium | Very large monolithic UI coordinator and CSS | Main JS and CSS hold unrelated responsibilities | Split incrementally, maintaining unchanged data schemas and public UI contracts |
| Medium | CI screenshot capture is not a screenshot-diff approval process | Browser tests save images, but there is no approved baseline comparison | Add reviewed visual snapshots after design approval |
| Medium | Real synchronization and performance objectives have no device evidence | Test fixtures do not access a real user's Supabase account; no physical iPhone timing data | Use disposable two-device account and representative FB2/EPUB/PDF books |

The latest past DOM-engine report is `docs/engineering/2026-10-29-dom-pagination.md`. Its acceptance gaps remain open; this document does not supersede its test evidence.

## Release gates

Until all v2.0 requirements are addressed, this remains a review-only branch. No merging solely because lint/unit/browser checks pass. Release requires a physical installed-iPhone review for status-bar color and first/last glyphs, real two-device cloud deletion/recovery testing, and benchmark results. A failed check blocks release instead of being disabled.
