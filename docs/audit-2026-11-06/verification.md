# Libra: проверки и воспроизводимость

База работы: `8d0fdb60fb88a01ac6ea680f89aaa8eaafb65ee3`; ветка `audit/libra-qa-security-20261106`. Изолированная копия репозитория, Linux, Node 24.22.1. Playwright 1.56.1: Chromium 141 и WebKit 26 с мобильными параметрами iPhone 13. Это не физический iPhone. Недостающие Linux-библиотеки WebKit добавлены локально в runtime браузера; это не изменение приложения.

## Выполненные циклы

1. Исходный аудит: 110/110 unit-тестов отдельной Libra. Предыдущая основная ветка: 189/189 старых unit-тестов; актуальная ветка отдельно проверена финальными 187/187. npm audit выявил уязвимые development-пакеты Libra. Новые регрессии первоначально падали на неподправленном коде и на извлечённых функциях исходного собранного выпуска. Логи RED сохранены.
2. После исправлений: parser/storage/sync unit-регрессии, сборка и браузерные проверки. Полный прогон исходников сначала выявил пять проблем самих проверок; после исправлений 121/124, затем 124/124. Текущая сборка: 34/36 в промежуточном прогоне, затем 35/36 и 37/38. Разобраны причины: тесты измеряли ещё индексируемую подпись, выбирали html в Shadow DOM снимка и проверяли кнопку до завершения гидратации. Временная непрозрачность/геометрия, оригинальные тексты и данные не подменялись ради зелёного результата.
3. Финальная регрессия: актуальные результаты в `evidence/*acceptance.log`, unit/build-логах и отчётах зависимостей. Промежуточный финальный прогон source дал 122/124: два теста читали `innerText` в момент временного скрытия DOM при переразметке. Добавлено ожидание неизменённого текста без ослабления ожидаемого содержимого; отдельный тройной повтор геометрии/полей в обоих движках прошёл 18/18. Последующий полный прогон сохранён отдельно. Сохранённый текущий выпуск прошёл 38/38, включая два замера производительности.

Итоговый локальный допуск: **120/120 unit**, **124/124 e2e исходников**, **38/38 e2e сохранённого выпуска**, **11/11 регрессий функций текущего bundle**, **187/187 старых unit**, **3/3 offline-проверки сборки**. npm audit в обоих актуальных пакетах: 0 известных уязвимостей. Полные логи сохранены. Сведения о preview и границах допуска находятся в `evidence/summary.json`.

Внешний WebKit smoke: 8/8 сценариев на фактически опубликованном preview. Все 14 опубликованных файлов совпали с проверенным локальным выпуском по SHA-256; HTTP security headers подтверждены. Внешний Chromium smoke не смог открыть preview (`ERR_EMPTY_RESPONSE`); приложение в этих попытках не выполнялось. Это не пройденный сценарий и не подтверждённый дефект приложения. Локальные проверки Chromium выполнены полностью; внешний preview отдельно проверяется WebKit и побайтовым сравнением артефактов/заголовков.

## Команды

```sh
cd libra
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
npm run build
npx playwright install --with-deps chromium webkit
npx playwright test --workers=2

cd ../release-hotfix
npm ci --ignore-scripts
npm audit --audit-level=high
npm run build
npm test
npx playwright install --with-deps chromium webkit
npm run test:browser
```

`build.mjs` получает неизменяемые исходные артефакты выпуска, проверяет их SHA-1, применяет строго однократные замены, добавляет модуль сносок и пересчитывает SHA-256 каждого offline-файла. Нулевое или повторное совпадение шаблона останавливает сборку. Проверены все 11 хешей offline shell. Сохранена исходная модель обновления: открытая книга не переключается на смешанный набор файлов; новая версия активируется после закрытия старых окон. Полные совпадающие TS-исходники исходного выпуска всё ещё надо восстановить.

Добавлен workflow `.github/workflows/libra-audit-qa.yml`, проверяющий исходники и сохранённый выпуск отдельно без production-учётных данных. Локальные успешные запуски не означают, что GitHub Actions уже выполнился.

## Что реально проверялось

- Импорт FB2/EPUB, кодировки, иллюстрации и таблицы, главы, последняя строка, поля и размер шрифта, смена темы и viewport, закладки, цитаты, прочитанные книги.
- Повторное открытие физической страницы; первый touchend и подавление повторного click; удержание текста; быстрое закрытие/открытие EPUB; неперехватывающая касание уходящая панель.
- Резервная копия с исходными байтами, контрольными суммами, прогрессом и закладками; повреждённая копия не изменяет библиотеку.
- Два независимых браузерных контекста с синтетическим backend: байты книг, bookmarks, настройки, выход из аккаунта, офлайн-правки и последующее подключение. Unit-интеграции: конфликт ревизий, одновременные изменения, tombstones, поздние записи и подтверждения. Это не реальное двухустройственное испытание Supabase.
- Загрузка после отключения локального HTTP-сервера; обновление старого PWA, сохранение книги/позиции и последующая работа без сервера. WebKit синтетический `context.setOffline(true)` в раннем тесте обновления дал внутреннюю ошибку движка; итоговая проверка отключает сам сервер. Другие офлайн-проверки остаются выполненными.
- Безопасный показ HTML-подобного текста сноски; реальный EPUB с отдельным файлом примечаний и совпадающими ID; положение страницы до и после модального окна; закрытие и повторное открытие без сети.
- После независимого ревью дополнительно выполнены проверки A→B на всех четырёх операциях библиотеки, переключение во время чтения исходных байтов и принудительное переключение в конечном IDB callback. Начальная попытка привязки импорта к аккаунту выявила регрессию live FileList; полные e2e поймали её, список теперь копируется до первого await. Остановленные неуспешные прогоны не считаются пройденными.
- Малый безопасный XML с ENTITY, невалидный импорт; запрещённые script/onerror, внешние img/CSS/iframe в EPUB; CSP и заголовки staging.

## Оставшиеся ограничения

Нет физического iOS PWA, настоящей пары тестовых аккаунтов Supabase/staging, тестирования истечения/revocation токенов и полного fuzzing EPUB/ZIP. Полное соответствие всем пунктам WSTG/ASVS не заявляется. Полностью исключить старый плавающий сдвиг на две страницы по эмуляции нельзя. Успешные тесты не доказывают отсутствие всех ошибок.

Основной production-адрес и рабочая БД не изменены. Сборка опубликована отдельным preview для проверки; в браузерных активных security-тестах запросы к production Supabase блокируются. Отчёт о фактическом совпадении файлов preview: `evidence/preview-integrity.json`.

Корневой `npm run check` первоначально захватывал независимый пакет browser-тестов `release-hotfix` вместе с серверным приложением и падал на их типах. Пакет исключён из корневого tsconfig по той же схеме, что самостоятельная `libra`; исходники Libra отдельно проходят собственный `tsc --noEmit`, browser-тесты исполняются Playwright. Финальный корневой check прошёл.
